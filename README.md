## 배포 방식

`main` 브랜치에 푸시하면 워크플로가 저장소 전체를 그대로 Pages에 올립니다.
빌드 단계가 없습니다 — 두 자료 모두 **HTML·CSS·JS 정적 파일**이고 번들러·프레임워크를 쓰지 않습니다.

`actions/configure-pages@v5`의 `enablement: true`를 두었으므로 **첫 실행 때 Pages가 자동으로 켜집니다.**
저장소 설정에서 따로 켜지 않아도 됩니다. 다만 저장소가 비공개이면 조직·플랜에 따라 Pages가 제한될 수 있습니다.

첫 배포는 2~3분, 이후 갱신은 1분 내외입니다. 진행 상황은 저장소의 **Actions** 탭에서 볼 수 있습니다.

## 검색 노출과 접근 제한

- 모든 페이지에 `noindex, nofollow`를 넣고 `robots.txt`로 전체 크롤링을 막았습니다.
- **다만 접근 제한은 아닙니다.** 주소를 아는 사람은 누구나 열 수 있습니다.
  경쟁 입찰 건이므로 **발주사 담당자에게만** 전달해 주십시오.

## 공개하지 않는 파일

`.gitignore`로 아래를 제외했습니다 — 원격 저장소에 올라가지 않습니다.

| 제외 | 이유 |
| --- | --- |
| `제안서.md` | 제출용 원문. 단가·회사 수치가 들어 있습니다 |
| `요구사항.md` | 고객사 비공개 RFP를 분석한 내부 문서입니다 |
| `*.docx` `*.pptx` `*.xlsx` `*.pdf` | 원본 문서·대외비 자료 |
| `design/` | 대외비 디자인 자료 |

**웹 제안서는 원문에서 두 가지를 뺐습니다** — 월 단가·MD 단가 등 단가 관련 수치와,
임직원 수·설립 시기·소재지·고객사 수 등 회사를 특정하는 정보. 자세한 내용은 `proposal/README.md`에 적었습니다.

## 갱신하는 방법

두 자료의 소스를 고친 뒤 커밋·푸시하면 됩니다.

```bash
cd "<이 폴더>"
git add -A
git commit -m "웹 제안서 수치 갱신"
git push
```

각 자료의 폴더에 README가 있고, 그 안에 자체 검증 스크립트 사용법이 적혀 있습니다.
**수치를 고친 뒤에는 검증을 먼저 돌려 주십시오** — 제안서와 웹 제안서의 숫자가 어긋나면 잡아 줍니다.
