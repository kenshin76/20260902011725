# 비철금속 B2B 거래 플랫폼 — 프로토타입

위시켓 **158040** 공고와 `../요구사항.md`(RFP 분석)를 바탕으로 만든 화면 프로토타입입니다.
고객사에 URL로 전달해 **1차 버전의 화면과 흐름을 계약 전에 확인**하기 위한 자료입니다.

## 이 프로토타입이 답하려는 질문

공고가 규정한 현재 문제는 「거래 한 건의 진행상태와 변경내역이 한곳에 남지 않는다」입니다.
그래서 이 프로토타입의 기준은 하나입니다 — **전화로 받은 거래 한 건이 플랫폼 안에서 정산까지 도는가.**

## 요청업체가 강조한 부분 — 화면에서 직접 확인하실 수 있는 것

### 1. 12단계 상태 머신 + 변경이력 + 증빙 (STS-01~12, STS-H1~H5)

`거래 상세` 화면 하나에 12단계 전이 · 시간순 변경이력 · 단계별 증빙 첨부가 모입니다.

- **허용된 다음 상태만** 버튼으로 나옵니다. 나머지는 비활성 — 전이규칙이 데이터로 정해져 있습니다.
- 그 단계의 **필수 입력 항목이 비면 넘어가지 않습니다.** 화면에서 막는 것이 아니라 `changeStatus()`가 거절합니다.
- **필수 증빙**(상차사진·계근표·검수자료)이 없으면 역시 거절됩니다.
- 상태 갱신과 이력 추가를 **한 묶음**으로 처리합니다 — 이력 없이 상태만 바뀌는 경로가 없습니다.
- 이력은 **쌓기만** 합니다. 잘못 넣은 값은 수정이 아니라 **정정 이력을 추가**하고 원래 값도 남습니다.
- **되돌리기도 사유 없이는 처리되지 않고**, 이력에 「되돌리기」로 남습니다.

### 2. 대행 물량 등록 — 약 1분 (OPS-02 · LOT-09 · PRN-03)

전화를 받으면서 넣는 화면입니다. **한 화면 · 스크롤 없음 · 필수 6항목.**
화면 위쪽에 **경과 시간이 실측**되며 60초를 넘으면 색이 바뀝니다.
품목을 고르면 그 품목의 등급만 남고, 기준 단가가 옆에 표시됩니다. **대행입력자가 함께 기록**됩니다.

### 3. 8단 전체 현황판 (OPS-11 · OPS-09)

신규문의 · 승인대기 · 판매중 물량 · 구매제안 · 거래확정 · 운송중 · 검수대기 · 정산대기.
각 칸을 누르면 해당 목록으로 들어갑니다.
「다음 조치사항」은 별도로 관리하는 값이 아니라 **상태정의에 적어 둔 필수 입력 항목에서 자동으로 나옵니다.**

**앞의 세 칸은 회원·물량의 생애주기이고 뒤의 다섯 칸은 거래의 생애주기입니다.**
한 컬럼에 섞으면 「판매중인 물량」과 「운송중인 거래」가 같은 상태값에 들어가 이후 통계가 전부 어긋납니다.

### 4. 계근 · 검수 — 「예상」을 「실제」로 확정 (STS-07/08)

예상중량 → 계근 실중량, 등록등급 → 검수 판정등급을 **덮어쓰지 않고 나란히 보관**하고
입력 시 **차이를 화면에 함께 표시**합니다. 허용 오차(설정값 ±0.5%)를 넘으면 경고가 붙습니다.

### 5. 최종금액 자동계산 + 산출근거 (AUT-02 · STS-09)

계근 실중량과 판정등급으로 자동 계산하고 **어떤 규칙이 어떻게 적용됐는지 줄별로 표시**합니다 —
실중량 → 수분 공제 → 정미중량 → 제안 단가 → 등급 조정 → 적용 단가 → 소계 → 불순물 공제 → 운송비 → 최종금액.

**계산은 자동, 확정은 사람.** 확정 버튼을 누른 시점의 규칙을 **그대로 복제해 저장**합니다.

> **직접 확인해 보십시오.** `최종금액·정산` 화면의 「수분 공제율을 0.8% → 2.0%로 올려 봅니다」를 누르면
> **확정된 거래의 금액은 그대로**이고 **미확정 거래만 새 규칙으로 다시 계산**됩니다.

### 6. 상태 순서를 개발 없이 바꾸는 구조 (STS-H5)

RFP §9는 「위 거래 단계는 순서가 변경될 수 있습니다」라고 적었습니다.
그래서 상태 목록과 허용 전이를 **버전 있는 설정 데이터**로 두었습니다.

> **직접 확인해 보십시오.** `상태·전이 설정` 화면의 「v2 만들기 — 「하차완료」 단계 추가」를 누르면
> 13단계 새 버전이 생깁니다. **이미 시작한 거래는 v1을 계속 참조**하고 **새 버전은 이후 거래에만** 적용됩니다.

### 7. 접근 범위 격리 흐름 (MEM-05)

프로토타입에서는 판매자·구매자가 **본인이 당사자인 거래만** 보도록 역할별 화면 흐름을 확인합니다. 구매자에게는 **다른 사람의 제안 단가가 표시되지 않습니다.**
로그인 전 주소를 직접 열면 로그인 화면으로 이동합니다. 실제 구축에서는 이 화면 흐름에 더해, **서버가 권한을 검증하고 허용된 데이터만 반환**하도록 구현합니다.

### 8. 품목·등급을 개발 없이 (LOT-01/02 · §3 「핵심」)

`품목·등급 관리`에서 품목·기준단가·등급 조정률을 직접 바꿉니다.
**사용 중인 값은 삭제하지 않고 비활성화**합니다 — 선택 목록에서만 사라지고 과거 물량·거래는 그대로 조회됩니다.

### 9. 알림은 한 지점을 거칩니다 (AUT-04 · OPT-03)

`notify(대상, 종류, 거래번호)` 한 지점만 거치므로, 2차에서 문자·카카오를 붙일 때 **그 함수 안쪽만** 바꾸면 됩니다.

## 범위 지도 — 「하지 않는다」도 화면에 적었습니다

`범위 지도` 화면에 **요구사항 등록부 61개 ID를 한 줄씩** 놓고 각 ID의 구현 방법과 대응 화면을 연결했습니다.
추가 개발 범위 7건은 1차 포함(2건) / 2차 권고(5건) 판단과 근거를, 1차 제외 범위 10건은 「구현하지 않았습니다」를 그대로 적었습니다.

## 확인 방법

이 폴더에는 자동 검증 스크립트를 포함하지 않았습니다. 배포 전에는 아래 흐름을 브라우저에서 확인합니다.

- 역할별 메뉴 전환: 운영자 18개, 판매자 8개, 구매자 8개
- 로그인 전 직접 주소 접근: 로그인 화면으로 이동하는지
- 거래 상세: 필수 입력·증빙이 없을 때 상태 전이가 거절되는지
- 상태 설정: 새 버전 생성 후 기존 거래와 신규 거래의 적용 버전이 분리되는지
- 정산: 규칙 변경 뒤에도 확정 거래의 금액 스냅샷이 유지되는지
- 증빙: 프로토타입의 모의 첨부임을 명확히 표시하는지

## 확인 사항
